API: constrained Monte Carlo

Sampling under a fixed direction of the (weighted) magnetization, for the finite-temperature anisotropy. total_torque is public but unexported. Usage: the constrained-MC guide; the algorithm: the theory page.

SCEMonteCarlo.run_cmc — Function
run_cmc(H::TiledHamiltonian, constraint::MagnetizationConstraint;
        temperature = nothing, kT = nothing, kwargs...) -> CMCResult

Constrained Monte Carlo (docs/specs/constrained-mc.md): sample the canonical ensemble of H restricted to a fixed direction n̂ of the weighted magnetization of constraint (see MagnetizationConstraint), and measure the torque, whose average is the free-energy gradient — the finite-temperature magnetic anisotropy. Per cell of H, ⟨T⟩ = −n̂ × ∂f/∂n̂ with f = F/n_cells (the :torque observable; F the free energy of the direction of M). Provide exactly one of temperature (kelvin, converted with KB_EV — assumes an eV-fitted model) or kT (model energy units), scalar or collection; a collection runs in the given order with the chain carried over (an annealing ladder when ordered high → low), or restarted from the constrained start at each temperature with carryover = false.

One call samples ONE constraint direction. To scan directions, repeat the call or pass a vector of constraints, which runs them as independent lanes over threads:

run_cmc(H, constraints::AbstractVector{MagnetizationConstraint};
        observables = c -> cmc_observables(H, c), ntasks = nothing, seed, …)
    -> Vector{CMCResult}

One sweep is one attempt per active site, in site order, serial: a constrained site (nonzero weight) is the source of a pair move with a uniformly drawn partner that compensates the transverse change of M (Asselin et al., PRB 82, 054415); a weight-0 active site gets a plain single-spin Metropolis attempt; inactive sites stay frozen. The run is bit-reproducible for a fixed seed, independently of the thread count.

H = TiledHamiltonian(model; dims = (4, 4, 4))
r = run_cmc(H, MagnetizationConstraint(π / 4, 0.0); temperature = 300.0,
            measure_interval = 10, seed = 1)
r.points[1].stats[:torque].mean    # ⟨T⟩ per cell, Cartesian (model energy units)

Keyword arguments

  • sweeps_therm = 2_000, sweeps_measure = 10_000, measure_interval = 1, step = 0.6, adapt_target = 0.5, adapt_interval = 50, renorm_interval = 1_000, nbins = 32, seed = rand(UInt64) — as for run_mc. The acceptance that drives the thermalization-only step adaptation counts null moves as rejected attempts (see CMCResult). A measurement of the default observables costs one energy-gradient pass (:torque and :torque_frame share it), about half a constrained sweep, and every torque_observable adds a pass over its terms; the passes read the chain's cached tesseral rows and allocate nothing. Measured on Nd₂Fe₁₄B production models (4×4×4 supercell, 4352 sites; a pair and a three-body model): at the default measure_interval = 1 the measurements take about a third of the wall time (about half with two partial torques covering the model), 9–10 % at 5 (17 %), and 5 % at 10 (9 %). Consecutive sweeps are strongly correlated, so a measure_interval of 5–10 loses little statistics.
  • observables = cmc_observables(H, constraint), evaluables = cmc_evaluables(). A set from cmc_observables must be built for the same H and the same constraint (direction and resolved weights): a set built for another one is refused with an ArgumentError before the run starts.
  • init = nothing: the constrained start. nothing — every constrained site along sign(w) n̂, every other site along n̂ (deterministic, no RNG); otherwise a 3 × n_sites matrix or a vector of 3-vectors, rotated rigidly so that its weighted magnetization points along n̂ (refused when that magnetization is below 1e-8 Σ|w|). Pass a ground state (find_ground_state) for a model with antiparallel sublattices.
  • carryover = true: carry the chain across the temperature ladder; false returns to the constrained start at every temperature (no RNG is consumed).
  • checkpoint = nothing, checkpoint_interval = 0: a file path to write restartable checkpoints to, and the sweeps between periodic writes (0 ⇒ only at temperature boundaries) — as for run_mc. The file (kind "cmc", docs/specs/checkpoint-schema.md) also stores the constraint (direction bitwise, resolved weights) and the constrained start; continue with resume(path, H), which returns the full run's CMCResult, bit-identical to an uninterrupted run.
  • or_per_metropolis, sweep_tasks: not supported — giving either throws an ArgumentError. There is no overrelaxation in CMC, and the sweep is serial (the pair move couples every pair through M∥, so colour classes do not commute).

At the end of every temperature's thermalization the run warns when the adapted step sits at its lower clamp (many null moves — a large weight ratio) and when the constraint is weak, M∥ / Σ|w| < 0.05 (above the ordering temperature, or nearly cancelling weights); every warning names kT and n̂.

source
run_cmc(H::TiledHamiltonian, constraints::AbstractVector{MagnetizationConstraint};
        temperature = nothing, kT = nothing,
        observables = c -> cmc_observables(H, c), evaluables = cmc_evaluables(),
        ntasks = nothing, seed = rand(UInt64), checkpoint = nothing,
        kwargs...) -> Vector{CMCResult}

Run one independent constrained chain per constraint — a lane — over threads, and return their results in the order of constraints (docs/specs/constrained-mc.md D4). The keywords are those of the single-chain run_cmc and mean the same for every lane: temperature / kT, sweeps_therm, sweeps_measure, measure_interval, step, adapt_target, adapt_interval, renorm_interval, nbins, evaluables, init (rotated onto each lane's direction), carryover, checkpoint_interval — plus ntasks and the per-lane observables and checkpoint below.

cons = [MagnetizationConstraint(θ, 0.0) for θ in range(0, π / 2; length = 7)]
rs = run_cmc(H, cons; temperature = 300.0, measure_interval = 10, seed = 1)
[r.points[1].stats[:torque].mean for r in rs]    # ⟨T⟩ per cell, one per θ

Seeds and reproducibility. The lane seeds are drawn from a master Xoshiro(UInt64(seed)) as rand(master, UInt64) in lane order k = 1, 2, …, all before any lane runs; lane k is the single-chain run with its lane seed, which its result records (CMCResult.seed, also stored in the lane's checkpoint). So rs[k] is bit-identical to run_cmc(H, constraints[k]; seed = rs[k].seed, observables = observables(constraints[k]), …) with the same other keywords, and the whole vector is bitwise independent of ntasks and of the thread count (the lanes share no mutable state; H is only read). Duplicate constraints are allowed: they are independent replicas with distinct lane seeds.

Observables are a FUNCTION of the constraint, constraint -> Vector{Observable}, called once per lane in lane order on the calling task before any lane starts — :M_par, :constraint_residual, and :torque_frame measure along the constraint they were built for, so a single vector shared by every lane would measure every lane along one direction. Giving a vector (or anything that is not callable) throws an ArgumentError. Add observables of your own with c -> [cmc_observables(H, c); extra]. Every lane's set is also checked against the lane's constraint before any lane runs, so c -> obs returning one fixed vector built by cmc_observables for one direction is refused (ArgumentError, naming the lane) as soon as a lane has another direction or other weights. evaluables is one vector shared by every lane (evaluables read only the binned statistics, which do not depend on the direction). With ntasks ≥ 2 lanes measure and finalize concurrently, so observables and evaluables of your own must not share mutable state across lanes (the defaults hold none: each lane's measurement keeps its own scratch, in which :torque and :torque_frame share one gradient pass per measurement).

Threads. ntasks (default min(length(constraints), Threads.nthreads())) bounds the number of tasks: the lanes are split into contiguous blocks of cld(length(constraints), ntasks) lanes, one task per block, each running its lanes in order; ntasks = 1 runs every lane serially on the calling task.

Checkpoints. With checkpoint = path, lane k writes its own file "<stem>.lane<k>.jld2" — stem is path without a trailing ".jld2" (any letter case), else path itself; a path naming a directory is refused — an ordinary kind-"cmc" file holding the lane's constraint and seed. Continue an interrupted lane with resume(file, H) (with the observables that lane was given); a completed lane's file returns its stored result. There is no resume of the whole set: resume the unfinished lanes one by one. Files of an earlier call with the same stem are not removed: a lane that fails before its first write, or a re-run with fewer lanes, leaves the earlier files in place — check their constraint and seed (or use a fresh stem) before reusing them.

Failures and interrupts. Every argument is checked before any lane runs: an empty constraint vector, ntasks < 1, the temperatures and the other plan keywords, a vector or non-callable observables, a function that does not return a Vector{Observable}, the observable / evaluable checks, a set from cmc_observables built for another constraint or another H, every constraint's resolution against H and its constrained start from init, the checkpoint path, or_per_metropolis and sweep_tasks (unsupported, as for one chain); an unknown keyword is a MethodError at the call. A lane that throws does not stop the others: the failure is logged at once (@error, naming the lane and n̂), every other lane runs, and then all failures are thrown together as a CompositeException of CapturedExceptions in lane order, whatever ntasks. For long scans pass checkpoint: the completed lanes' files then return their results through resume. An InterruptException (Ctrl-C on the caller, or raised in a lane) stops every block from starting another lane and logs a warning saying so; lanes already running are NOT stopped mid-run — they finish (and write their files) — and run_cmc throws a bare InterruptException once every task has finished.

SCEMonteCarlo.CMCResult — Type
CMCResult

Result of run_cmc: points (one TempResult per temperature, in run order), the constraint — a MagnetizationConstraint with the run's direction (bitwise) and its weights resolved against the Hamiltonian (a per-cell-atom vector, also when the run was given :auto / :uniform / :magmoms; signed zeros folded to +0.0) — the chain's final_config, and the run seed.

In a constrained run acceptance_metropolis is the accepted fraction of ALL attempts of the measurement phase: pair attempts (null moves — proposals the compensation cannot realize — count as rejected attempts) and the single-spin attempts of weight-0 sites, pooled. acceptance_or is NaN (no overrelaxation in CMC). Prints as a summary table: the mean Cartesian torque (torque_x, torque_y, torque_z) and M∥, per cell of H. The error bar of a projection of the torque (onto ê_θ, ê_φ, or any fixed axis) cannot be built from the per-component errors (their covariance is not kept): read it from the :torque_frame statistics, which are binned directly.

SCEMonteCarlo.MagnetizationConstraint — Type
MagnetizationConstraint(direction::AbstractVector{<:Real}; weights = :auto)
MagnetizationConstraint(direction::NTuple{3,Real}; weights = :auto)
MagnetizationConstraint(θ::Real, φ::Real; weights = :auto)

The constraint of a constrained Monte Carlo run: the direction n̂ of the weighted magnetization M = Σ_{s∈𝒞} w_{a(s)} e_s is held fixed (docs/specs/constrained-mc.md D1). The sampled measure is the canonical one restricted to M̂ = n̂ with the factor |M|² of the solid-angle delta function, so that the mean torque is the gradient of the free energy F(n̂) of the canonical distribution of M̂.

  • direction — any finite nonzero 3-vector or 3-tuple; it is normalized (stored unit). The angle form uses the physics convention n̂ = (sinθ cosφ, sinθ sinφ, cosθ): θ is the polar angle from +z, φ the azimuth from +x toward +y.
  • weights — one of
    • :auto (the default) — resolved against the Hamiltonian of the run: its moments magmoms (μ_B per cell atom) when it carries them, otherwise 1 for every cell atom. Either way never signed (moments are ≥ 0), so it constrains the direction of the net moment; for an antiferromagnet or near a compensation point that net moment nearly cancels, and the run warns (weak constraint) at the end of thermalization — give such a model signed weights;
    • :uniform — 1 for every cell atom;
    • :magmoms — the moments of the Hamiltonian (refused when it has none);
    • a vector of finite real numbers, one per training-cell atom of the Hamiltonian in its atom order (the reduced cell's order after reduce_cell). Weights may be negative (an antiparallel sublattice enters M with its sign flipped) or zero (that atom's sites are not constrained and are updated by plain single-spin Metropolis).

The constrained set 𝒞 is the active sites whose atom has a nonzero weight; inactive sites never enter M. Symbolic weights are resolved, and the length of a weight vector checked, against the Hamiltonian of the run.

Two constraints compare equal (==, isequal, hash) when their stored direction and weights are equal field by field (signed zeros are folded to +0.0 at construction, so the three agree). The weight vector is copied at construction; do not mutate c.weights afterwards (it would change the hash; the finiteness is re-checked when the constraint is resolved against a Hamiltonian).

SCEMonteCarlo.cmc_observables — Function
cmc_observables(H::TiledHamiltonian, constraint::MagnetizationConstraint)
    -> Vector{Observable}

The default observables of a constrained run (run_cmc) on H under constraint (conventions: docs/specs/binning-observables.md B5; torque conventions: docs/specs/constrained-mc.md D5). Every observable is per cell of H: n_cells = n_sites ÷ n_cell_atoms is the number of cells of H in the supercell (the cells of the reduced cell after reduce_cell):

  • :energy, :energy2 — total energy and its square (model units, j0 excluded), as in standard_observables;
  • :torque — the total torque per cell of H, total_torque(H, config) / n_cells, Cartesian (3 components; unweighted, Zeeman part included). Averaged, it is the free-energy gradient of the constrained direction: ⟨T⟩ = −n̂ × ∂f/∂n̂ with f = F/n_cells;
  • :M_par — the constrained magnetization along the constraint, M·n̂ / n_cells with M = Σ_{s∈𝒞} w_{a(s)} e_s (units of the weights per cell of H — μ_B per cell for weights = :magmoms);
  • :constraint_residual — |M⊥| / M∥ (radians: the angle between M and n̂, to first order), a rounding-level diagnostic of the pair moves;
  • :torque_frame — the same torque in the spherical frame of the constraint direction, (ê_φ·T, ê_θ·T, n̂·T) / n_cells (3 components); in a run, from the SAME gradient evaluation as :torque (one gradient per measurement serves both). For n̂ = (sinθ cosφ, sinθ sinφ, cosθ), ê_φ = (−sinφ, cosφ, 0) and ê_θ = (cosθ cosφ, cosθ sinφ, −sinθ), so averaged ⟨ê_φ·T⟩ = −∂f/∂θ, ⟨ê_θ·T⟩ = (1/sinθ) ∂f/∂φ, ⟨n̂·T⟩ = 0. At the poles the frame is the φ = 0 limit (ê_φ = ŷ; ê_θ = x̂ at +ẑ, −x̂ at −ẑ). Its error bars are binned directly: the error of a projection cannot be built from the per-component errors of :torque (their covariance is not kept);
  • :torque_zeeman (only when H carries a field, has_field) — the analytic Zeeman part of :torque, MU_B_EV_T (M_μ × B) / n_cells with M_μ = Σ_{active s} m_{a(s)} e_s — always the moments of H, whatever the constraint weights.

Build them with the SAME constraint the run uses: :M_par, :constraint_residual, and :torque_frame measure along the direction (and with the weights) of the constraint they were built for. run_cmc and resume check this when the run starts and throw an ArgumentError for a set built for another constraint or another H — near a pole also when only the :torque_frame axes differ (observables of your own are not inspected). The weights are resolved against H here (the errors of the constraint resolution surface at this call). The measuring functions are bound to this H object: measuring them in a run on any other TiledHamiltonian throws an ArgumentError. They hold no mutable state, so one set may be shared by concurrent lanes.

Cost: inside run_cmc (and run_mc) :torque and :torque_frame share one energy-gradient pass per measurement, read from the chain's cached tesseral rows without allocating; called directly (or from run_pt), each evaluates total_torque on its own — bitwise the same values. One gradient pass costs about half a constrained sweep; thin the measurements with measure_interval (measured costs: run_cmc).

SCEMonteCarlo.cmc_evaluables — Function
cmc_evaluables() -> Vector{Evaluable}

The default evaluables of a constrained run: :specific_heat only, with the definition of standard_evaluables (per active site, units of k_B). The fluctuation formula stays exact in the constrained ensemble — its reference measure does not depend on the temperature — while the susceptibility and the Binder cumulant change meaning under a fixed direction of M, so they are left out.

SCEMonteCarlo.torque_observable — Function
torque_observable(name::Symbol, Hpart::TiledHamiltonian, H::TiledHamiltonian)
    -> Observable

A 3-component Observable named name that measures the torque of the term-subset Hamiltonian Hpart on the configuration of a run on H: total_torque(Hpart, config) / n_cells (Cartesian, per cell of H, unweighted — the normalization of :torque; see total_torque and docs/specs/constrained-mc.md).

Build Hpart with the public constructor from the SAME term list that built H (after reduce_cell: red.terms), filtered to the subset of interest and without a field — e.g. TiledHamiltonian(n, filter(t -> t.body == 1, terms); dims) for the on-site part. Over a disjoint cover of the fitted terms the partial torques plus the analytic Zeeman torque sum to the total torque, configuration by configuration; an individual partial torque is a free-energy gradient only to first order in the anisotropy.

Doors (ArgumentError, every message naming the argument order — the term subset Hpart second, the run's H third): Hpart and H must agree on n_cell_atoms, dims, and n_sites; Hpart must carry no field (the Zeeman part is measured analytically); every template of Hpart must equal — in atoms, shifts, ls, folded, and the scaled coefficient — one of the fitted templates H.terms[1:H.n_fitted_terms], so a subset of a different term list (another cell, another fit) is refused even when the atom counts happen to agree. Disjointness and coverage are not enforced.

The observable is bound to the H object it was built with: measuring it in a run on any other TiledHamiltonian (even an equal one) throws an ArgumentError — run_cmc and the resume of a constrained run refuse it before the run starts — so build it with the same H the run uses. Hpart and H are immutable and the returned function captures no mutable state, so the observable may be shared across lanes that sample the same H.

Cost: one gradient pass over the terms of Hpart per measurement. In run_mc and run_cmc it reads the chain's cached tesseral rows and allocates nothing (bitwise the value of a direct call, which rebuilds the rows and allocates the gradient vector); see measure_interval of run_cmc for measured costs.

SCEMonteCarlo.total_torque — Function
total_torque(H::TiledHamiltonian, config::SpinConfig) -> SVector{3,Float64}

Total torque of the full system, T = Σ_{s active} G_s × e_s = −Σ_s e_s × ∂E/∂e_s, with G the tangent-projected gradient of energy_gradient! — so the Zeeman part of a field-carrying H is included, and every term counts with unit weight (never the constraint weights). Model energy units (eV for an eV-fitted model); a full-system sum, not per cell or per site.

Meaning: for a rigid rotation of every spin by the angle α about a unit axis w, T · w = −dE/dα. Averaged in the constrained ensemble it is the free-energy gradient ⟨T⟩ = −n̂ × ∂F/∂n̂ (docs/specs/constrained-mc.md). Inactive sites have G_s = 0 and contribute nothing. For an isotropic (rotation-invariant) model the sum vanishes configuration by configuration.

One call costs about one Metropolis sweep (it rebuilds the tesseral rows and allocates the gradient vector).
